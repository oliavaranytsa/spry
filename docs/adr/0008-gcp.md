# ADR 0008: What Spry would be on Google Cloud, and moving its core there

- **Status:** accepted (core moved; the rest stays on AWS)
- **Date:** 2026-11-13
- **Lab:** 9, "One project, two clouds"

## Context

Spry runs on AWS and is described in Terraform (ADR 0007). The question: what
would it take to run it on Google Cloud, and what would it cost? The constraints:
the same code wherever possible, no long-lived keys, a student budget (Free
Trial credit, a $5 budget alert), and nothing left running that bills by the
hour once the lab is over.

## Decision: service by service

| Spry on AWS | On Google Cloud | Decision | Why |
|---|---|---|---|
| S3 + CloudFront + WAF, static frontend | Firebase Hosting | **replace** | CDN and HTTPS included, free plan. A rewrite sends `/api/**` to Cloud Run: one origin, no CORS, as CloudFront did |
| Lambda + function URL, FastAPI | Cloud Run | **replace** | The `runtime` stage of the same Dockerfile that Compose runs; no Mangum, no 15-minute limit, scales to zero |
| ECR | Artifact Registry | **replace** | 0.5 GB free; a cleanup policy keeps the newest 3 images |
| Aurora Serverless v2 (0–1 ACU, pauses) | Cloud SQL for PostgreSQL, db-f1-micro | **replace** | Keeps SQL, the models and the Alembic migrations unchanged. Does not pause: stopped by hand outside use, destroyed after the lab |
| Secrets Manager (`DATABASE_URL`) | Secret Manager | **replace** | Terraform generates the password and writes the whole URL as one secret; Cloud Run injects it as `DATABASE_URL` |
| Cognito user pool + Google | Identity Platform | **keep on AWS** | The API already verifies Cognito tokens from anywhere; the Firebase site is just one more callback URL. One user base for both clouds. Identity Platform is the stretch goal |
| EventBridge Scheduler + SQS + builder/mailer Lambdas | Cloud Scheduler + Pub/Sub/Cloud Tasks + Cloud Run | **keep on AWS** (later: replace) | The weekly report is not part of the core; it runs fine where it is |
| S3 event → Lambda | Cloud Storage + Eventarc → Cloud Run | **keep on AWS** | Part of the report |
| SES | none on Google Cloud | **keep SES** | If the report moved: SendGrid or Mailgun, API key in Secret Manager, read by the service account that sends |
| Bedrock (Claude Haiku 4.5) | Vertex AI (Gemini, or Claude via Model Garden) | **keep on AWS** | The parser works; the trial credit does not pay for partner models on Vertex. Compared in Vertex AI Studio (Part 4) |
| SSM / Secrets Manager | Secret Manager | **replace** (above) | |
| CloudWatch Logs | Cloud Logging | **replace** | Automatic for Cloud Run |
| IAM roles | Service accounts + IAM roles | **replace** | `spry-api` (Cloud SQL client, one secret) for the service; `spry-terraform` with the six roles this config needs, for CI later. No Owner/Editor, no keys |
| Terraform `aws` provider, workspace `spry-dev` | `google` provider, workspace `spry-gcp` | **add** | `gcp/`, its own state, so one plan cannot break both clouds |
| GitHub OIDC role | Workload Identity Federation | **later** | Stretch: GitHub presents an OIDC token, Google exchanges it for `spry-terraform`; condition on the numeric repository id |

### The database

| Option | Latency | Bill (idle month) | Code |
|---|---|---|---|
| Cloud SQL around the clock | lowest (same region as Cloud Run) | ≈ $9.40 | unchanged |
| **Cloud SQL, stopped when not in use** (chosen for the lab) | same, but the first request after a start waits for it | ≈ $1.70 storage + $0.0105 per running hour | unchanged |
| Firestore | low | $0 within the daily free quota | the whole data layer rewritten as documents: no joins, no migrations, queries designed per screen |
| Keep Aurora on AWS, call across clouds | +100–150 ms a query (us-central1 → us-east-1/eu-north-1), many queries per page; and Aurora is in a private VPC, so it would need a public endpoint or a VPN | Aurora as now + egress | unchanged, but slow and exposed |

Cloud SQL wins for the lab because it moves the app without touching the code;
the cost is handled by stopping it. For a long-lived free deployment Firestore
is the only $0 option, and the price is a rewrite.

**Data:** the database was created empty and filled by the Alembic migrations,
which the container runs on start. Aurora was not dumped: it sits in a private
VPC with no route from outside, and the data is demo data.

### E-mail

There is no Google e-mail service. If the weekly report moved, it would send
through SendGrid (free 100 a day) or Mailgun; the API key would be a Secret
Manager secret readable only by the report job's service account. Until then
SES on AWS keeps sending, which a multicloud setup allows.

### What does not move, and why

- **Sign-in (Cognito):** moving it means every user signs up again (passwords
  cannot be exported from Cognito). Keeping one pool lets both copies of the
  site share accounts.
- **The weekly report and the agenda parser:** not part of the core; they would
  be rewritten around Cloud Scheduler, Pub/Sub, Eventarc and Vertex AI, and the
  parser's model choice was already settled on Bedrock (ADR 0006).

## Consequences

- Moved without changes: the FastAPI code (one small public endpoint added,
  `GET /api/health/db`, which proves the database answers), the models, the
  migrations, the frontend code. Changed: `entrypoint.sh` reads `PORT`; the
  Cognito client accepts the Firebase site as a callback.
- The lock-in is not in compute (a container runs anywhere) but in the managed
  services around it: Cognito, SES, Bedrock, EventBridge.
- Multicloud costs: the browser now signs in on AWS and calls Google; tokens
  cross clouds but no data does. Splitting the database from the API across
  clouds was rejected for latency.
- `terraform destroy` in `gcp/` removes everything this lab created, the
  database included. The state holds the generated password (in HCP Terraform,
  encrypted at rest), as ADR 0007 already accepts for `DATABASE_URL`.
